# Deploying SprayMaster

This directory holds Infrastructure-as-Code blueprints for two complementary
deployments:

| Where  | What                                  | Why                                          |
| ------ | ------------------------------------- | -------------------------------------------- |
| Render | Full FastAPI web UI in **demo mode**  | Long-running uvicorn, WebSocket, SQLite disk |
| Vercel | Static landing page that links to it  | Fast global CDN, project pitch, install docs |

> **About SAFE_DEMO mode.** SprayMaster is a dual-use credential-testing tool.
> Public clouds (Render, Vercel, most PaaS) prohibit outbound credential attacks
> in their AUPs regardless of intent. The Render service therefore boots with
> `SPRAYMASTER_SAFE_DEMO=1`: the full UI, history, API, and metrics are live,
> but `POST /attacks` returns `403`. Run real attacks from a host you control,
> against systems you are **authorized** to test.

## 1 · Deploy the web UI to Render

The repo root ships a `render.yaml` Blueprint. It provisions:

- one Docker web service (built from the repo's `Dockerfile`)
- a 1 GB persistent disk mounted at `/home/sprayer/.spraymaster` for SQLite history
- `SPRAYMASTER_SAFE_DEMO=1` (attacks disabled)
- `SPRAYMASTER_AUTH_TOKEN` auto-generated by Render and stored as a secret
- `/healthz` wired up as the health-check path

### Steps

1. **Push to GitHub** if you haven't already:
   ```bash
   git push -u origin main
   ```
2. Open <https://dashboard.render.com> → **New** → **Blueprint** → pick the
   `SprayMaster` repo. Render reads `render.yaml` and shows you the plan.
3. Click **Apply**. First Docker build takes ~6–8 minutes (it installs the
   `[all]` extras — every protocol).
4. Once the service is **Live**, open it → **Environment** tab → reveal
   `SPRAYMASTER_AUTH_TOKEN`. Copy the value.
5. Open the public URL → `/login`, paste the token. You're in.

### Customising

- **Pick a different region:** edit `region:` in `render.yaml` (e.g. `frankfurt`,
  `singapore`, `ohio`).
- **Bigger disk:** bump `sizeGB`. SQLite is small; 1 GB holds millions of rows.
- **Free vs Starter plan:** the Blueprint uses `plan: starter` ($7/mo) so the
  service doesn't spin down. Change to `plan: free` to make it free-tier
  (cold-start ~30 s after 15 min idle, and the free plan does **not** support
  persistent disks — drop the `disk:` block if you switch).
- **Rotate the token:** in Render's Environment tab, regenerate
  `SPRAYMASTER_AUTH_TOKEN` and restart the service.
- **Run actual attacks (NOT recommended on Render):** set
  `SPRAYMASTER_SAFE_DEMO=0`. Be prepared for the service to be terminated for
  AUP violation — credential attempts originating from Render's IP space trip
  their abuse detection.

### Health & metrics

- Liveness: `GET /healthz` → `ok` (no auth)
- Prometheus: `GET /metrics` (auth required — `Authorization: Bearer <token>`)
- API: `GET /api/runs`, `GET /api/runs/{id}/findings` (auth required)

## 2 · Deploy the landing page to Vercel

The static landing page in `deploy/vercel/` pitches the project and links to
the Render demo + GitHub repo. It's a single HTML/CSS file — no build step,
no JS framework, no functions.

### Steps

1. Edit `deploy/vercel/index.html` and replace the demo URL placeholder
   (`https://spraymaster-web.onrender.com`) with whatever URL Render assigned
   to your service.
2. Install the Vercel CLI: `npm i -g vercel`
3. From the repo root, deploy:
   ```bash
   cd deploy/vercel
   vercel deploy --prod
   ```
   Or, from the Vercel dashboard, **Add New** → **Project** → import the GitHub
   repo and set the **Root Directory** to `deploy/vercel`. No framework preset
   needed.
4. (Optional) Attach a custom domain in the Vercel dashboard.

`vercel.json` sets sane security headers (CSP, `X-Frame-Options`,
`Referrer-Policy`, `Permissions-Policy`) for the static site.

## 3 · Local verification

Before pushing, sanity-check the demo mode locally:

```bash
# Demo mode on, public bind allowed because attacks are gated
SPRAYMASTER_SAFE_DEMO=1 SPRAYMASTER_AUTH_TOKEN=local-test spraymaster-web --port 8000
# In another shell:
curl -i -X POST http://127.0.0.1:8000/attacks \
  -H "Authorization: Bearer local-test" \
  --data-urlencode protocol=ssh \
  --data-urlencode targets=10.0.0.1 \
  --data-urlencode users=admin \
  --data-urlencode passwords=hunter2
# → HTTP/1.1 403 Forbidden ... "SAFE_DEMO mode ..."
```

Or build the Docker image exactly as Render will:

```bash
docker build -t spraymaster:demo .
docker run --rm -p 8000:8000 \
  -e SPRAYMASTER_SAFE_DEMO=1 \
  -e SPRAYMASTER_AUTH_TOKEN=local-test \
  -v spraymaster-data:/home/sprayer/.spraymaster \
  spraymaster:demo spraymaster-web
```

## 4 · Other PaaS targets

The same pattern works on Fly.io, Railway, Koyeb, Heroku, and any Docker host:

| Platform | What to set                                                                  |
| -------- | ---------------------------------------------------------------------------- |
| Fly.io   | `fly launch` → use `Dockerfile`, set secrets `SPRAYMASTER_SAFE_DEMO=1` etc. |
| Railway  | New service from Docker → set the same env vars                              |
| Koyeb    | New Docker service, port 8000, env vars as above                             |

The CLI auto-detects `$PORT` and binds `0.0.0.0` when it's present, so no
flags are needed in the start command — just `spraymaster-web`.
